# Git / GitHub 基本操作マニュアル

このファイルは、広島大学硬式野球部 野球プロジェクトのリポジトリにおいて、メンバーが手動でGitHubとファイルの送受信（プルやプッシュ等）を行う際の基本的な操作手順をまとめたものです。

---

## 1. 最新のデータを取得する（Pull）
他のメンバーやAIが更新した最新の状態を、自分のパソコンにダウンロードします。
競合（コンフリクト）を防ぐため、**作業を始める前には必ず毎回**この操作を行ってください。

```bash
# 最初に、必ず作業対象のフォルダ（リポジトリ）に移動します
cd "c:\Users\スコアボード\Documents\野球\プロジェクト\project_baseball"

# GitHubにある最新データをローカル（自分のPC）へ反映します
git pull origin main
```

---

## 2. 変更をリポジトリに保存・共有する（Add, Commit, Push）
自分が新しく作ったファイルや、編集したファイルをGitHubにアップロードしてチーム内に共有する手順です。３つのステップに分かれています。

### ステップ A：変更したファイルを指定する（Add）
「変更したファイルの中で、どれをGitHubにアップロードするか」を選び、送信候補（ステージング）に登録します。

```bash
# 特定のファイルだけをアップロード対象にする場合
git add ファイル名.拡張子
# 例: git add test.pptx

# フォルダ内にある変更されたファイル（新規・修正）を「すべて」対象にする場合
git add .
```

### ステップ B：変更内容に名前をつける（Commit）
「何の目的で変更・追加したのか」、後から他の人が見てもわかるように短いメモ（コミットメッセージ）をつけて、保存を確定（コミット）します。

```bash
# -m のあとの ""(ダブルクォーテーション) 内に、わかりやすい変更内容を書きます
git commit -m "変更内容や理由をここに書く"
# 例: git commit -m "分析用のテスト用パワーポイントを追加"
```

### ステップ C：GitHubへアップロードする（Push）
手元のPCで確定させた内容を、クラウド上のGitHubリポジトリへ実際に送信（プッシュ）します。

```bash
# origin(リモートサーバー) の mainブランチ（主軸のデータ）へ送信します
git push origin main
```

---

## よくあるトラブルへの対応

### プッシュに失敗する場合
「自分と他の人が同じタイミングでデータを変更した」ことが原因等でエラーが出ることがあります。その際は、以下のように対応してください。
1. まず、落ち着いて `git pull origin main` を行います。
2. 競合箇所（コンフリクト）があればそれを修正します。
3. 修正後、再度 `git add .` → `git commit -m "競合を解決"` → `git push origin main` を行います。

### プッシュすべきではないデータについて
AGENT.md で定義されている通り、以下のデータはプッシュしないでください。プッシュ前に `git status` コマンドで確認する癖をつけると安全です。
- **個人情報:** 選手名などの機密情報を含むファイル。
- **巨大なデータ:** 動画ファイルや大規模な練習・試合データ。これらは Git の管理外にするため、`Data/` フォルダ等に保存してください。
